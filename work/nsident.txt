      ( *** nsident - nearstar_identity, and the one cast boundary Wave 4
	    closes ***

	This is a LIBRARY.  It needs fpabi, fpctl, fpx87, fpconv and
	fpchains, which the top-level programme lists BEFORE it.  It
	modifies none of them: FLOATPOLICY.md's contract and
	tests/test_floatcontract.py stay literally true, because everything
	new lives in Wave 4's own namespace.

	----------------------------------------------------------------
	THE CHAIN
	----------------------------------------------------------------

	    NOCTIS-0.CPP:4078
	    nearstar_identity = x/100000*y/100000*z/100000

	Five operations, ONE store, left associated exactly as C requires,
	on the x87 stack at control word 133Fh.  That schedule is Wave 3's
	NsIdentity fragment, generated by tools/genfp.py from fpsched.txt
	and pinned 4113/4113 against STARMAP.BIN by test_floatcontract.py.
	NsIdentityD does not re-derive it - it CALLS it, so the two cannot
	drift.  Under a plain IEEE-double engine the same expression scores
	2239/4113; under lino's native floats, 4.  Do NOT evaluate this by
	calling the scalar fpx87 routines in sequence: each of them stores,
	and that is FLOATPOLICY battery 7, also 2239.

	----------------------------------------------------------------
	NsIdentChop16 - the hole in FLOATPOLICY 3.3, closed for ONE site
	----------------------------------------------------------------

	    NOCTIS-0.CPP:3970  (extract_ap_target_infos)
	    srand (ap_target_x/100000*ap_target_y/100000*ap_target_z/100000)

	Borland passes that expression to __ftol on the x87 stack: there is
	no memory round trip, so __ftol truncates the LIVE EXTENDED value.
	FLOATPOLICY 3.3 records that the delivered fpconv cannot do this -
	FToIntChop begins `fld qword [FA0]`, which has already narrowed the
	value to binary64 - and leaves the boundary UNSETTLED.  Wave 4
	closes it for this one site and no other.

	The fragment below is the NsIdentity fragment with its terminal
	`fstp id` replaced by fldcw-chop / fistp QWORD on the live st(0) /
	fldcw restore.  Borland's __ftol returns the low 32 bits of that 64-bit
	integer result.  A dword store instead produces 80000000h when the
	identity exceeds signed 32-bit, which changes the stellar class.  The
	eight instructions before that are byte-identical to
	NsIdentity's, and they are identical by CONSTRUCTION rather than by
	transcription: the fidiv operand is fpchains' own generated constant
	FKNsIdentityK100000, not a copy of it.  A hand-written fragment that
	quietly drifts from the generated schedule is the obvious failure
	mode here; sharing the constant slot removes half of it, and the
	regression test's opcode-prefix check removes the rest.

	Why not add this to fpsched.txt: test_floatcontract.py (a) requires
	fpchains.txt to be byte-identical to what fpsched.txt regenerates
	and (b) asserts fpchains.txt contains NO fistp encoding at all.
	Generalising this into genfp is a Wave-3.1 tidy-up with its own test
	edit, not a side effect of Wave 4.

	NOTE THE ASYMMETRY, again: srand's int16 is ZERO extended, because
	Borland's srand writes an explicit 0 into the seed's high word.
	random()'s int16 is SIGN extended.  This routine returns the
	zero-extended form, 0..65535.

	----------------------------------------------------------------
	INTERFACE
	----------------------------------------------------------------

	    NsIdentityD    in  FJ0 FJ1 FJ2 = x y z, int32
			   out FA0/FA1 and nsid0/nsid1 = the binary64
			   pre  caller is inside FEnter with [FCW]=133Fh

	    NsIdentChop16  in  FJ0 FJ1 FJ2 = x y z, int32
			   out A and FI = the low 16 bits, unsigned
			   pre  as above.  Leaves the x87 stack balanced.

	    NsIdentAddInt  in  nsid0/nsid1 and FI = n
			   out FA0/FA1 = fl(identity + (double)n)
			   ONE binary64 add, because Borland pushes
			   search_id_code's argument as 8 bytes, so the
			   value IS a binary64 at the call boundary.     )

"variables"

	nsid0	= 0;		( nearstar_identity, low half  )
	nsid1	= 0;		( nearstar_identity, high half )

	nsicsav = 0;		( __ftol's own control-word save slot.  NOT
				  shared with FCWSAV or with fpconv's
				  FCWCSAV: a routine that borrowed either
				  would silently replace the word FLeave is
				  supposed to put back. )
	nsicchop = 0;
	nsicq0 = 0;		( __ftol qword result, low half first )
	nsicq1 = 0;

	nsidsav0 = 0;
	nsidsav1 = 0;

"programme"

( ==================================================================== )

      ( NsIdentityD - the graded chain, called not copied. )

"NsIdentityD"
	=> NsIdentity;
	A = [FA0]; [nsid0] = A;
	A = [FA1]; [nsid1] = A;
	end;

( ==================================================================== )

      ( NsIdentChop16 - the same eight instructions, then __ftol on the
	live st(0), then Borland's zero-extended 16 bits. )

"NsIdentChop16"
	[nsicsav] = 0;
	{
	    9B					(fwait)
	    D9 BF <dnsicsav mtp bytesperunit>	(fnstcw [edi+nsicsav*4])
	}
	A = [nsicsav]; A & 0F3FFh; A | 0C00h; [nsicchop] = A;
	{
	    DB 87 <dFJ0 mtp bytesperunit>		(fild   x)
	    DA B7 <dFKNsIdentityK100000 mtp bytesperunit>(fidiv K100000)
	    DB 87 <dFJ1 mtp bytesperunit>		(fild   y)
	    DE C9					(fmulp  st1,st0)
	    DA B7 <dFKNsIdentityK100000 mtp bytesperunit>(fidiv K100000)
	    DB 87 <dFJ2 mtp bytesperunit>		(fild   z)
	    DE C9					(fmulp  st1,st0)
	    DA B7 <dFKNsIdentityK100000 mtp bytesperunit>(fidiv K100000)
	    D9 AF <dnsicchop mtp bytesperunit>		(fldcw  chop)
	    DF BF <dnsicq0 mtp bytesperunit>		(fistp  qword [nsicq0])
	    D9 AF <dnsicsav mtp bytesperunit>		(fldcw  restore)
	}
	A = [nsicq0]; A & 0FFFFh; [FI] = A;
	end;

( ==================================================================== )

      ( NsIdentAddInt - FA <- fl(nearstar_identity + (double)FI).

	NOCTIS-0.CPP:4367 calls search_id_code (nearstar_identity + n, 'P').
	This one is correct precisely BECAUSE it stores: the argument is
	pushed as eight bytes, so the value crossing the call boundary is a
	binary64.  One op, one store, faithful. )

"NsIdentAddInt"
	=> IntToF;			( FA = (double)n, exact )
	A = [FA0]; [FB0] = A;
	A = [FA1]; [FB1] = A;
	A = [nsid0]; [FA0] = A;
	A = [nsid1]; [FA1] = A;
	=> FAdd;
	end;
