      ( *** fpx87 - the X87 backend, Level 2 (SCALAR) ***

	One of three interchangeable backends.  Link exactly one.  All
	three export the same period names and read and write the same
	fpabi register file, so a call site never changes.

	WHAT THIS FILE IS FOR, AND WHAT IT IS NOT FOR.
	These are the SCALAR routines: one operation, result to memory.
	They are correct for every site where the ORIGINAL also stored to
	a declared variable.  They are WRONG for a generation expression,
	because each one ends in fstp and that store is a rounding that
	Borland's code did not do.  One spilled intermediate costs 1055 of
	4194 STARMAP records.  Generation calls fpchains, not this file.

	CLOBBERING CONTRACT.
	  - the ML fragments touch ONLY the x87 stack and the fpabi
	    variables.  They never touch A/B/C/D/E and never touch edi.
	  - the L.in.oleum glue around them DOES use A and E, following the
	    stock library convention that a subroutine need not preserve
	    registers.
	  - every routine leaves the x87 stack exactly as it found it.
	    FStackOK reads TOP back so a caller can assert that.

	OPCODE NOTE.  The reversed-operand pairs on the x87 are a classic
	source of silent wrong answers, so for the record:
	    DE E8+i is FSUBP  ST(i),ST(0)    ST(i) = ST(i) - ST(0)
	    DE E0+i is FSUBRP ST(i),ST(0)    ST(i) = ST(0) - ST(i)
	    DE F8+i is FDIVP  ST(i),ST(0)
	    DE F0+i is FDIVRP ST(i),ST(0)
	Nothing here relies on that; the chains in fpchains do.        )

      ( FLoad - FA <- FB.  A pure copy: no FPU involved, so no rounding
	and no chance of a stack imbalance. )

"FLoad"
	A = [FB0]; [FA0] = A;
	A = [FB1]; [FA1] = A;
	end;

"FAdd"
	{
	    DD 87 <dFA0 mtp bytesperunit>	(fld  qword [edi+FA0*4])
	    DC 87 <dFB0 mtp bytesperunit>	(fadd qword [edi+FB0*4])
	    DD 9F <dFA0 mtp bytesperunit>	(fstp qword [edi+FA0*4])
	}
	end;

"FSub"
	{
	    DD 87 <dFA0 mtp bytesperunit>	(fld  qword [edi+FA0*4])
	    DC AF <dFB0 mtp bytesperunit>	(fsub qword [edi+FB0*4])
	    DD 9F <dFA0 mtp bytesperunit>	(fstp qword [edi+FA0*4])
	}
	end;

"FMul"

      ( FAtan2 - FA <- atan2(FA, FB), i.e. atan(FA/FB) with the quadrant
	taken from both signs, which is what fpatan does.  st1 holds the
	numerator and st0 the denominator, so FA is pushed first. )

"FAtan2"
	{
	    DD 87 <dFA0 mtp bytesperunit>	(fld  qword [edi+FA0*4])
	    DD 87 <dFB0 mtp bytesperunit>	(fld  qword [edi+FB0*4])
	    D9 F3				(fpatan)
	    DD 9F <dFA0 mtp bytesperunit>	(fstp qword [edi+FA0*4])
	}
	end;

      ( FCmp - FI <- -1 if FA<FB, 0 if equal, +1 if FA>FB.

	FCOMPP compares ST(0) against ST(1) and pops both, so FB goes on
	first and FA second.  The condition codes land in the status
	word: C3 is bit 14, C2 is bit 10, C0 is bit 8.

	    A > B   C3=0 C2=0 C0=0
	    A < B   C3=0 C2=0 C0=1
	    A = B   C3=1 C2=0 C0=0
	    unord.  C3=1 C2=1 C0=1

	Unordered would otherwise read as "equal", which is the wrong
	answer rather than a missing one, so C2 is tested FIRST and sets
	FFLGUNORD.  No Noctis vector should ever reach it. )

"FCmp"
	[FSW] = 0;
	{
	    DD 87 <dFB0 mtp bytesperunit>	(fld qword [edi+FB0*4])
	    DD 87 <dFA0 mtp bytesperunit>	(fld qword [edi+FA0*4])
	    DE D9				(fcompp)
	    9B					(fwait)
	    DD BF <dFSW mtp bytesperunit>	(fnstsw [edi+FSW*4])
	}
	A = [FSW]; A & 0400h;
      ? A != 0 -> FCMP unord;
	A = [FSW]; A & 4000h;
      ? A != 0 -> FCMP eq;
	A = [FSW]; A & 0100h;
      ? A != 0 -> FCMP lt;
	[FI] = 1;
	end;
    "FCMP eq"
	[FI] = 0;
	end;
    "FCMP lt"
	A = 0; A - 1; [FI] = A;
	end;
    "FCMP unord"
	A = [FFLG]; A | FFLGUNORD; [FFLG] = A;
	[FI] = 2;
	end;
