      ( *** spncc - the .NCC arena: loadpv, unloadallpv, copypv, modpv,
	    the pvlist walk, QuickSort and drawpv's dispatch ***

	THE FILE FORMAT is 2 + 50n bytes: a uint16 polygon count, then n
	bytes of vertices-per-polygon, then X, Y and Z as float32 arrays
	of 4n each, then n colour bytes.  ONLY THREE MODELS ARE EVER
	LOADED - VEHICLE, MAMMAL and BIRDY - and the other four .NCC files
	in the distribution are never touched by the game.

	THE TRAP.  For a triangle the fourth vertex slot holds
	UNINITIALISED GARBAGE.  Measured over the shipped VEHICLE: 150 of
	the 156 triangle slot-3 components are non-zero, 26 exceed 1e6 in
	magnitude, 2 are not finite at all, and the largest finite one is
	2.99e38 - one multiply away from infinity.  loadpv ZEROES THOSE
	SLOTS BEFORE the scale-and-move pass; reorder the two and the
	transform produces infinities and NaNs that then propagate through
	the midpoints and the depth sort.

	BIRDY CANNOT SEE THIS.  Its 55 non-zero slot-3 components max out
	at 20.0, so a corpus containing only BIRDY grades the zeroing pass
	VACUOUSLY: with or without it, nothing overflows.  VEHICLE has to
	be in the corpus for the check to mean anything.

	THE ARENA LAYOUT TRANSFERS VERBATIM, one Noctis byte per unit.
	BUFFERMODEL 5 alias 9 directs a re-layout so every float sub-array
	is unit aligned; that is OVERRULED (see spmem's header) and the
	float sub-arrays are read through spmem's 4-unit assemble pair
	instead.  The consequence that matters here: pvfile_c is n bytes
	long and the colour loop runs to 4n, so it writes 3n bytes past
	the end - and with the DOS offsets intact those 3n bytes land
	inside pv_mid_x, which is zeroed before anything reads it.  The
	overrun is FAITHFULLY DEAD rather than conditionally dead, and it
	is graded by an ADDRESS CENSUS only.  A check of the form "the
	drawn model matches" cannot fail on it and is not filed as
	covering it.

	pv_mid_x[handle] == 0 IS A SENTINEL AND OFFSET 0 IS A LEGAL ARENA
	OFFSET.  In the shipped load order mamm_base is loaded first and
	therefore sits at arena offset 0, so porting the null-pointer
	trick would make the first handle loaded believe it has no depth
	sort.  This port carries a separate per-handle boolean.  That is a
	real collision, not a hypothetical one.

	pv_dep_i IS PERSISTENT STATE.  It is set to the identity ONCE, in
	loadpv, and every frame's QuickSort permutes the previous frame's
	array.  copypv resets the two animal handles each frame because it
	copies the WHOLE block including pv_dep_i; vehicle_handle is never
	copypv'd and therefore sorts incrementally across the entire
	session.  "Any correct sort" is a different program - the array is
	reproduced as state and the swap sequence is emitted.

	unloadpv IS NOT IMPLEMENTED.  Every loadpv sequence in the shipped
	game is preceded by unloadallpv, so unloadpv is unreachable.  Not
	implemented, not graded, and said so here rather than left to be
	inferred from an absent check.

	drawpv MODE 2 (randomic_mapper) IS OUT OF SCOPE, and so - as a
	declared deviation from the wave plan - are modes 0 and 1's
	PIXELS.  This file emits the DISPATCH: the polygon order, the
	vertex base index, the vertex count, the colour and, for mode 1,
	the mangled colour.  Routing the dispatch into Wave 6a's poly3d
	and polymap would make the graded artifact a joint product of two
	waves, so that a page difference could not be attributed.  The
	dispatch is the part Wave 6b owns and it is graded exactly.      )

( ==================================================================== )
( model staging                                                         )
( ==================================================================== )

      ( SP ncc load : read the three .NCC files into nccraw, one byte per
	unit, and record base / length / polygon count for each.  The
	polygon count is READ from the file's first two bytes and the
	2 + 50n identity is CHECKED, not assumed. )

"SP ncc load"
	[NCtop] = 0;
	[PVmodel] = 0;
    "SP nl m"
	A = [PVmodel];
	? A = MDVEH -> SP nl veh;
	? A = MDMAM -> SP nl mam;
	[File Name] = spbrdname; -> SP nl rd;
    "SP nl veh"
	[File Name] = spvehname; -> SP nl rd;
    "SP nl mam"
	[File Name] = spmamname;
    "SP nl rd"
	[File Position]	= 0;
	[File Command]	= READ;
	[Block Pointer]	= stage;
	[Block Size]	= STAGEMAX;
	[Block Size]	* BYTESPERUNIT;
	isocall;
	A = [Block Size]; [SPfbytes] = A;
	? A '> 0 -> SP nl ok;
	C = [SPload]; C | 4; [SPload] = C;
	-> SP nl next;
    "SP nl ok"
	( spread into nccraw )
	[SPMi] = 0;
    "SP nl b"
	A = [SPMi]; C = A; C > 2; D = stage; D + C;
	C = [D];
	A = [SPMi]; A & 3; A '* 8;
	C > A; C & 255;
	A = nccraw; A + [NCtop]; A + [SPMi];
	[A] = C;
	[SPMi]+;
	A = [SPMi]; ? A '< [SPfbytes] -> SP nl b;

	A = [PVmodel]; A '* 4; C = nccidx; C + A;
	[C plus 0] = [NCtop];
	[C plus 1] = [SPfbytes];
	A = nccraw; A + [NCtop];
	D = [A plus 1]; D & 255; D < 8;
	E = [A plus 0]; E & 255; D + E;
	A = [PVmodel]; A '* 4; C = nccidx; C + A;
	[C plus 2] = D;
	( 2 + 50n identity )
	A = D; A '* 50; A + 2;
	? A = [SPfbytes] -> SP nl sz;
	C = [SPload]; C | 8; [SPload] = C;
    "SP nl sz"
	A = [NCtop]; A + [SPfbytes]; [NCtop] = A;

    "SP nl next"
	[PVmodel]+;
	A = [PVmodel]; ? A '< NMODEL -> SP nl m;
	end;

      ( SP pvh at : A <- the pvh slot base of handle [PVh]. )

"SP pvh at"
	A = [PVh]; A '* PVSLOT; A + pvhtab;
	end;

"SP unloadallpv"
	[PVtop] = 0;
	[SPMi] = 0;
    "SP ua h"
	A = [SPMi]; A '* PVSLOT; A + pvhtab;
	[A plus 2] = 0;
	[SPMi]+;
	A = [SPMi]; ? A '< PVHN -> SP ua h;
	end;

      ( the sub-array byte offsets, all derived from dataptr and n.
	These ARE the DOS numbers: +0, +n, +17n, +33n, +49n, +50n, +54n,
	+58n, +62n, +66n.  A re-laid-out arena fails on every one. )

"SP pv addrs"
	=> SP pvh at;
	[PVcnt]   = [A plus 0];
	[PVptr] = [A plus 1];
	[PVds]  = [A plus 3];
	A = [PVptr];                    [PVac] = A;	( n_vtx )
	A = [PVptr]; C = [PVcnt];         A + C; [PVax] = A;
	A = [PVptr]; C = [PVcnt]; C '* 17; A + C; [PVay] = A;
	A = [PVptr]; C = [PVcnt]; C '* 33; A + C; [PVaz] = A;
	A = [PVptr]; C = [PVcnt]; C '* 49; A + C; [PVj] = A;
	A = [PVptr]; C = [PVcnt]; C '* 50; A + C; [PVamx] = A;
	A = [PVptr]; C = [PVcnt]; C '* 54; A + C; [PVamy] = A;
	A = [PVptr]; C = [PVcnt]; C '* 58; A + C; [PVamz] = A;
	A = [PVptr]; C = [PVcnt]; C '* 62; A + C; [PVamd] = A;
	A = [PVptr]; C = [PVcnt]; C '* 66; A + C; [PVadi] = A;
	end;

( ==================================================================== )
( loadpv                                                                )
( ==================================================================== )

"SP loadpv"
	[PVret] = 0;
	A = [PVh]; ? A '>= PVHN -> SP lp out;

	=> SP pvh at;
	[A plus 2] = 0;			( datalen = 0 )
	[A plus 1] = [PVtop];		( dataptr = datatop )
	[A plus 3] = 0;			( the depth-sort flag, NOT a null pointer )

	A = [PVmodel]; A '* 4; C = nccidx; C + A;
	[NCbase] = [C plus 0];
	[NCn]    = [C plus 2];

	=> SP pvh at;
	[A plus 0] = [NCn];
	[PVcnt] = [NCn];

	( datatop += 50n, in the same five steps the original takes )
	A = [PVtop]; C = [PVcnt]; C '* 50; A + C; [PVtop] = A;

	( memory check BEFORE reading )
	A = [PVtop]; ? A '<= PVBYTES -> SP lp room;
	=> SP pvh at;
	[PVtop] = [A plus 1];
	-> SP lp out;
    "SP lp room"

	( one _read of datatop - dataptr bytes, straight into the arena )
	=> SP pv addrs;
	[SPreg] = RGPVF;
	[SPMi] = 0;
	A = [PVcnt]; A '* 50; [SPMk] = A;
    "SP lp rd"
	A = nccraw; A + [NCbase]; A + 2; A + [SPMi];
	[SPval] = [A];
	A = [PVptr]; A + [SPMi]; [SPidx] = A;
	=> SP dput;
	[SPMi]+;
	A = [SPMi]; ? A '< [SPMk] -> SP lp rd;

	( ZERO THE UNUSED VERTEX SLOTS - and this happens HERE, before the
	  scale pass, which is the whole trap. )
	[PVp] = 0;
	A = [PVcnt]; ? A = 0 -> SP lp ds;
    "SP lp z"
	[SPreg] = RGPVF;
	A = [PVac]; A + [PVp]; [SPidx] = A; => SP dget;
	A = [SPval]; ? A != 3 -> SP lp zn;
	A = [PVp]; A '* 16; A + 12; [SPMk] = A;
	[SPf] = 0;
	A = [PVax]; A + [SPMk]; [SPidx] = A; => SP putf32;
	[SPf] = 0;
	A = [PVay]; A + [SPMk]; [SPidx] = A; => SP putf32;
	[SPf] = 0;
	A = [PVaz]; A + [SPMk]; [SPidx] = A; => SP putf32;
    "SP lp zn"
	[PVp]+;
	A = [PVp]; ? A '< [PVcnt] -> SP lp z;

    "SP lp ds"
	A = [PVreq]; ? A = 0 -> SP lp xf;
	A = [PVtop]; C = [PVcnt]; C '* 18; A + C; [PVtop] = A;
	A = [PVtop]; ? A '<= PVBYTES -> SP lp dsok;
	=> SP pvh at;
	[PVtop] = [A plus 1];
	-> SP lp out;
    "SP lp dsok"
	=> SP pvh at;
	[A plus 3] = 1;
	=> SP pv addrs;

    "SP lp xf"
	( the scale / move / colour pass, c = 0 .. 4n-1.

	  Each component is  float *= float  then  float += float, so
	  each of the six operations narrows to binary32 on the way back
	  into the array.  Doing the whole thing at double and narrowing
	  once is a different answer.

	  The colour add runs to 4n over an n-byte array.  That is the
	  overrun; it is counted, not clamped. )
	[PVovn] = 0; [PVovlo] = 0; [PVovhi] = 0;
	[SPreg] = RGPVF;
	[PVc] = 0;
	A = [PVcnt]; A '* 4; [SPMk] = A;
	A = [SPMk]; ? A = 0 -> SP lp mid;
    "SP lp c"
	A = [PVc]; A '* 4; [PVi] = A;

	A = [PVax]; A + [PVi]; [SPidx] = A; => SP getf32;
	[PGFt] = [PVxs]; => SP fb32;
	[PGFt] = [SPf]; => PGF ldf32; => FMul; => F32Narrow;
	[PGFt] = [PVxm]; => SP fb32;
	=> FAdd; => F32Narrow; => PGF stf32;
	[SPf] = [PGFt];
	A = [PVax]; A + [PVi]; [SPidx] = A; => SP putf32;

	A = [PVay]; A + [PVi]; [SPidx] = A; => SP getf32;
	[PGFt] = [PVys]; => SP fb32;
	[PGFt] = [SPf]; => PGF ldf32; => FMul; => F32Narrow;
	[PGFt] = [PVym]; => SP fb32;
	=> FAdd; => F32Narrow; => PGF stf32;
	[SPf] = [PGFt];
	A = [PVay]; A + [PVi]; [SPidx] = A; => SP putf32;

	A = [PVaz]; A + [PVi]; [SPidx] = A; => SP getf32;
	[PGFt] = [PVzs]; => SP fb32;
	[PGFt] = [SPf]; => PGF ldf32; => FMul; => F32Narrow;
	[PGFt] = [PVzm]; => SP fb32;
	=> FAdd; => F32Narrow; => PGF stf32;
	[SPf] = [PGFt];
	A = [PVaz]; A + [PVi]; [SPidx] = A; => SP putf32;

	( pvfile_c[handle][c] += base_color, for c up to 4n )
	A = [PVptr]; C = [PVcnt]; C '* 49; A + C; A + [PVc]; [SPidx] = A;
	=> SP dget;
	C = [SPval]; C + [PVcol]; C & 255; [SPval] = C;
	A = [PVptr]; C = [PVcnt]; C '* 49; A + C; A + [PVc]; [SPidx] = A;
	=> SP dput;
	A = [PVc]; ? A '< [PVcnt] -> SP lp cn;
	[PVovn]+;
	A = [PVovn]; ? A != 1 -> SP lp ovc;
	[PVovlo] = [SPidx]; [PVovhi] = [SPidx];
	-> SP lp cn;
    "SP lp ovc"
	A = [SPidx]; ? A '>= [PVovlo] -> SP lp ovh;
	[PVovlo] = A;
    "SP lp ovh"
	A = [SPidx]; ? A '<= [PVovhi] -> SP lp cn;
	[PVovhi] = A;
    "SP lp cn"
	[PVc]+;
	A = [PVc]; ? A '< [SPMk] -> SP lp c;

    "SP lp mid"
	A = [PVds]; ? A = 0 -> SP lp fin;
	=> SP pv midpoints;
	( the identity permutation, written ONCE - every later frame
	  permutes this array rather than rebuilding it )
	[PVp] = 0;
	A = [PVcnt]; ? A = 0 -> SP lp fin;
    "SP lp di"
	[SPreg] = RGPVF;
	[SPf] = [PVp];
	A = [PVadi]; C = [PVp]; C + C; A + C; [SPidx] = A;
	=> SP putu16;
	[PVp]+;
	A = [PVp]; ? A '< [PVcnt] -> SP lp di;

    "SP lp fin"
	=> SP pvh at;
	C = [PVtop]; D = [A plus 1]; C - D;
	[A plus 2] = C;
	[PVret] = 1;
    "SP lp out"
	end;

      ( SP pv midpoints : the arithmetic mean of the USED vertices, and
	the divisor is the loop variable c left over from the inner loop -
	which is exactly nv, but is written that way in the original and
	is therefore written that way here. )

"SP pv midpoints"
	=> SP pv addrs;
	[SPreg] = RGPVF;
	[PVp] = 0;
	A = [PVcnt]; ? A = 0 -> SP pm done;
    "SP pm p"
	[SPf] = 0; A = [PVp]; C = A; C + C; C + C;
	A = [PVamd]; A + C; [SPidx] = A; => SP putf32;
	[SPf] = 0; A = [PVp]; C = A; C + C; C + C;
	A = [PVamx]; A + C; [SPidx] = A; => SP putf32;
	[SPf] = 0; A = [PVp]; C = A; C + C; C + C;
	A = [PVamy]; A + C; [SPidx] = A; => SP putf32;
	[SPf] = 0; A = [PVp]; C = A; C + C; C + C;
	A = [PVamz]; A + C; [SPidx] = A; => SP putf32;

	A = [PVac]; A + [PVp]; [SPidx] = A; => SP dget;
	[PVnv] = [SPval];
	A = [PVnv]; ? A = 0 -> SP pm next;

	[PGFt] = 0; => PGF ldf32; [PGFi] = SFV0; => PGF sa;
	[PGFt] = 0; => PGF ldf32; [PGFi] = SFV1; => PGF sa;
	[PGFt] = 0; => PGF ldf32; [PGFi] = SFV2; => PGF sa;
	[PVv] = 0;
    "SP pm v"
	A = [PVp]; A '* 16; C = [PVv]; C + C; C + C; A + C; [PVi] = A;
	A = [PVax]; A + [PVi]; [SPidx] = A; => SP getf32;
	[PGFt] = [SPf]; => PGF ldf32; [FB0] = [FA0]; [FB1] = [FA1];
	[PGFi] = SFV0; => PGF a; => FAdd; => F32Narrow; [PGFi] = SFV0; => PGF sa;
	A = [PVay]; A + [PVi]; [SPidx] = A; => SP getf32;
	[PGFt] = [SPf]; => PGF ldf32; [FB0] = [FA0]; [FB1] = [FA1];
	[PGFi] = SFV1; => PGF a; => FAdd; => F32Narrow; [PGFi] = SFV1; => PGF sa;
	A = [PVaz]; A + [PVi]; [SPidx] = A; => SP getf32;
	[PGFt] = [SPf]; => PGF ldf32; [FB0] = [FA0]; [FB1] = [FA1];
	[PGFi] = SFV2; => PGF a; => FAdd; => F32Narrow; [PGFi] = SFV2; => PGF sa;
	[PVv]+;
	A = [PVv]; ? A '< [PVnv] -> SP pm v;

	[FI] = [PVnv]; => IntToF; [PGFi] = SFV3; => PGF sa;
	[PGFi] = SFV0; => PGF a; [PGFi] = SFV3; => PGF quo; => F32Narrow;
	=> PGF stf32; [SPf] = [PGFt];
	A = [PVp]; C = A; C + C; C + C; A = [PVamx]; A + C; [SPidx] = A;
	=> SP putf32;
	[PGFi] = SFV1; => PGF a; [PGFi] = SFV3; => PGF quo; => F32Narrow;
	=> PGF stf32; [SPf] = [PGFt];
	A = [PVp]; C = A; C + C; C + C; A = [PVamy]; A + C; [SPidx] = A;
	=> SP putf32;
	[PGFi] = SFV2; => PGF a; [PGFi] = SFV3; => PGF quo; => F32Narrow;
	=> PGF stf32; [SPf] = [PGFt];
	A = [PVp]; C = A; C + C; C + C; A = [PVamz]; A + C; [SPidx] = A;
	=> SP putf32;

    "SP pm next"
	[PVp]+;
	A = [PVp]; ? A '< [PVcnt] -> SP pm p;
    "SP pm done"
	end;

( ==================================================================== )
( copypv                                                                )
( ==================================================================== )

      ( _fmemmove of the WHOLE block - geometry, colours, midpoints AND
	pv_dep_i.  That last one is why the animals restart from the
	identity every frame while the vehicle sorts incrementally: the
	vehicle is never copypv'd. )

"SP copypv"
	[PVret] = 0;
	A = [PVh]; ? A '>= PVHN -> SP cp out;
	A = [PVk]; ? A '>= PVHN -> SP cp out;

	A = [PVk]; A '* PVSLOT; A + pvhtab; [PVj] = [A plus 2];
	A = [PVj]; ? A = 0 -> SP cp out;
	A = [PVh]; A '* PVSLOT; A + pvhtab;
	C = [A plus 2]; ? C != [PVj] -> SP cp out;

	A = [PVk]; A '* PVSLOT; A + pvhtab; [PVi] = [A plus 1];
	A = [PVh]; A '* PVSLOT; A + pvhtab; [PVc] = [A plus 1];

	[SPreg] = RGPVF;
	A = [PVi]; A + RPVF; A + nw; [SPcpfrom] = A;
	A = [PVc]; A + RPVF; A + nw; [SPcpto] = A;
	( Both handles are fixed, contiguous, non-overlapping ranges in the same
	  one-byte-per-Lino-unit arena.  Resolve their workspace addresses first,
	  then copy exactly the stored block length through ESI/EDX. )
	{
	    56
	    8B B7 <dSPcpfrom mtp bytesperunit>
	    8D 34 B7
	    8B 97 <dSPcpto mtp bytesperunit>
	    8D 14 97
	    8B 8F <dPVj mtp bytesperunit>
	    85 C9
	    74 0D
	    8B 06
	    89 02
	    83 C6 04
	    83 C2 04
	    49
	    75 F3
	    5E
	}
	[SPMi] = [PVj]; A = [PVc]; A + [PVj]; A - 1; [SPidx] = A;
	A = [SPcpto]; C = [A]; C & 255; [SPval] = C;
	[PVret] = 1;
    "SP cp out"
	end;

( ==================================================================== )
( QuickSort - the exact partition, with an explicit stack               )
( ==================================================================== )

      ( The original recurses.  L.in.oleum's subroutine stack is not a
	place to put an unbounded recursion, so the two calls are pushed
	onto an explicit LIFO in the order that makes them POP in the
	original's order: (iq,end) first, then (start,jq).  The partition
	itself is untouched, and the SWAP SEQUENCE is emitted, so "any
	correct sort" does not pass.

	The pivot is mdist[index[(start+end)/2]] and it is read ONCE, as
	a float, before the partition begins - so a later swap that moves
	the pivot element does not change the pivot value. )

      ( SP qs load : FA <- mdist[index[[QStmp]]] )

"SP qs key"
	[SPreg] = RGPVF;
	A = [QSidx]; C = [QStmp]; C + C; A + C; [SPidx] = A;
	=> SP getu16;
	A = [QSdst]; C = [SPf]; C + C; C + C; A + C; [SPidx] = A;
	=> SP getf32;
	[PGFt] = [SPf]; => PGF ldf32;
	end;

"SP quicksort"
	[QSswap] = 0;
	A = [PVcnt]; ? A '< 2 -> SP qs done;
	[QSsp] = 0;
	A = qstk;
	[A plus 0] = 0;
	C = [PVcnt]; C - 1; [A plus 1] = C;
	[QSsp] = 1;

    "SP qs pop"
	A = [QSsp]; ? A = 0 -> SP qs done;
	A - 1; [QSsp] = A;
	A '* 2; C = qstk; C + A;
	[QSs] = [C plus 0];
	[QSe] = [C plus 1];

	[QSiq] = [QSs];
	[QSjq] = [QSe];
	A = [QSs]; C = [QSe]; A + C; A / 2; [QStmp] = A;
	=> SP qs key; [PGFi] = SFT2; => PGF sa;		( xq )

    "SP qs outer"
	A = [QSiq]; ? A > [QSjq] -> SP qs part done;
    "SP qs adv i"
	[QStmp] = [QSiq]; => SP qs key;
	[PGFi] = SFT2; => PGF b; => FCmp;
	A = [FI]; ? A != 1 -> SP qs adv j;
	[QSiq]+;
	-> SP qs adv i;
    "SP qs adv j"
	[QStmp] = [QSjq]; => SP qs key;
	[PGFi] = SFT2; => PGF b; => FCmp;
	A = [FI]; ? A >= 0 -> SP qs test;
	A = [QSjq]; A - 1; [QSjq] = A;
	-> SP qs adv j;
    "SP qs test"
	A = [QSiq]; ? A > [QSjq] -> SP qs part done;

	( swap index[iq] and index[jq], and record the pair )
	[SPreg] = RGPVF;
	A = [QSidx]; C = [QSiq]; C + C; A + C; [SPidx] = A; => SP getu16;
	[PVi] = [SPf];
	A = [QSidx]; C = [QSjq]; C + C; A + C; [SPidx] = A; => SP getu16;
	[PVj] = [SPf];
	[SPf] = [PVj];
	A = [QSidx]; C = [QSiq]; C + C; A + C; [SPidx] = A; => SP putu16;
	[SPf] = [PVi];
	A = [QSidx]; C = [QSjq]; C + C; A + C; [SPidx] = A; => SP putu16;

	A = [QSswap]; ? A '>= 3999 -> SP qs noswaprec;
	A = [QSswap]; A + A; C = pvswap; C + A;
	[C plus 0] = [QSiq];
	[C plus 1] = [QSjq];
    "SP qs noswaprec"
	[QSswap]+;

	[QSiq]+;
	A = [QSjq]; A - 1; [QSjq] = A;
	-> SP qs outer;

    "SP qs part done"
	( push (iq,end) first so that (start,jq) is processed first )
	A = [QSiq]; ? A >= [QSe] -> SP qs p2;
	A = [QSsp]; A '* 2; C = qstk; C + A;
	[C plus 0] = [QSiq];
	[C plus 1] = [QSe];
	[QSsp]+;
    "SP qs p2"
	A = [QSs]; ? A >= [QSjq] -> SP qs pop;
	A = [QSsp]; A '* 2; C = qstk; C + A;
	[C plus 0] = [QSs];
	[C plus 1] = [QSjq];
	[QSsp]+;
	-> SP qs pop;

    "SP qs done"
	end;

      ( SP dw emit one : one dispatch record.

	    unit 0  the draw ORDER index p
	    unit 1  the polygon id c that p selects
	    unit 2  the vertex base i = 4c
	    unit 3  pv_n_vtx[c]
	    unit 4  pvfile_c[c]
	    unit 5  the mode-1 mangled colour

	MODE 1's MANGLE is  k = (k & 0xC0) | ((k & 0x3F) >> 1)  and it is
	written out for every mode, because it is a pure function of the
	colour and grading it only on the mode-1 cases would leave it
	unexercised whenever the corpus happens to carry none.

	MODE 2's p-versus-c DEFECT is reproduced in unit 6:  the sorted
	branch reads "pv_n_vtx[handle][p] == 4" where every other read in
	the same expression uses c.  With the three shipped models it is
	unobservable - BIRDY is 20 triangles and VEHICLE's mode-2 calls
	pass use_depth_sort = 0, so p and c coincide - and it is graded
	only against a synthetic mixed-nv model. )

"SP dw emit one"

	A = [DWn]; A '* 8; C = pvcall; C + A;
	[C plus 0] = [PVp];
	[C plus 1] = [PVc];
	D = [PVc]; D + D; D + D;
	[C plus 2] = D;
	[C plus 3] = [PVnv];
	[C plus 4] = [PVk];
	A = [PVk]; A & 192; D = [PVk]; D & 63; D > 1; A | D;
	[C plus 5] = A;
	( the mode-2 read that uses p where the rest of the line uses c )
	A = [PVac]; A + [PVp]; [SPidx] = A; => SP dget;
	A = [DWn]; A '* 8; C = pvcall; C + A;
	[C plus 6] = [SPval];
	[C plus 7] = [DWmode];
    "SP de skip"
	[DWn]+;
	end;

( modpv                                                                 )
( ==================================================================== )

      ( ROTATION ORDER Y, then X, then Z, and the two scales are applied
	ON THE STORE rather than as a clean R.S composition:

	    x1 = (x-cx)*cos_y + (z-cz)*sin_y
	    z1 = (z-cz)*cos_y - (x-cx)*sin_y
	    z  = z_scale * (z1*cos_x + (y-cy)*sin_x) + cz
	    y1 = (y-cy)*cos_x - z1*sin_x
	    x  = x_scale * (x1*cos_z + y1*sin_z) + cx
	    y  = y_scale * (y1*cos_z - x1*sin_z) + cy

	Note that Z is STORED BACK before y1 is computed, and y1 uses the
	ORIGINAL y - so the order of the six lines is load bearing.  The
	six sines and cosines are FLOATS, computed once from the degree
	angles through deg = M_PI/180.

	THE pvlist WALK IS A do{}while, so it executes ONCE even when
	pv_n_vtx[c] is zero, and the four flags are Borland bitfields
	packed LOW BITS FIRST: polygon_id in bits 0..11, then vtxflag_0
	at bit 12 through vtxflag_3 at bit 15.  The list terminates on
	polygon_id == 0xFFF. )

"SP modpv"
	A = [PVh]; ? A '>= PVHN -> SP mo out;
	=> SP pvh at;
	A = [A plus 2]; ? A = 0 -> SP mo out;
	=> SP pv addrs;
	[MOwalk] = 0;

	[PGFt] = [MOxa]; => PGF ldf32;
	[PGFt] = DDEGL; [PGFu] = DDEGH; => PGF ldf64; [FB0] = [FA0]; [FB1] = [FA1];
	[PGFt] = [MOxa]; => PGF ldf32; => FMul;
	[PGFi] = SFT0; => PGF sa;
	[PGFi] = SFT0; => PGF a; => FSin; => F32Narrow; [PGFi] = SFSNX; => PGF sa;
	[PGFi] = SFT0; => PGF a; => FCos; => F32Narrow; [PGFi] = SFCSX; => PGF sa;

	[PGFt] = DDEGL; [PGFu] = DDEGH; => PGF ldf64; [FB0] = [FA0]; [FB1] = [FA1];
	[PGFt] = [MOya]; => PGF ldf32; => FMul;
	[PGFi] = SFT0; => PGF sa;
	[PGFi] = SFT0; => PGF a; => FSin; => F32Narrow; [PGFi] = SFSNY; => PGF sa;
	[PGFi] = SFT0; => PGF a; => FCos; => F32Narrow; [PGFi] = SFCSY; => PGF sa;
