( ==================================================================== )
( battery 4 - THE CANARY THAT CAN FAIL                                  )
( ==================================================================== )

      ( DEFECT 5.  FBDUMP kind 6 v1 was 18 units in which BOTH the
	"expected" and the "actual" field held 0xA5A5A5A5, written by
	construction on both sides.  A clean run and a build with the
	walker stubbed out produced a BIT-IDENTICAL record, so the check
	could not fail, which is worse than no check.  The old "O1b canary
	table dumped clean" compared can[i] against can[i+1] - two copies
	of one literal - and passed for every build ever made.

	v2 is 4 units per pad, eleven pads, and NO LITERAL is stored.
	Every unit is either read back out of the workspace or produced by
	the walker:

	  0  clean read : nw[padbase(i) + slot(i)] AFTER poisoning
	  1  dirty read : the same address after storing WITNESS(i)
	  2  fired      : the pad index + 1 the walker reported
	  3  at         : the nw offset of the first violation

	THIS IS DELIBERATELY NOT fbshell's "FB canary battery".  That one
	sweeps slot = (7i+1) mod 12 and folds four bits of the poison into
	its witness; this one sweeps slot = (5i+3) mod 12 and folds eight.
	Two independent walks over the same contract, and w5spec.py knows
	all four fields from the LAYOUT alone - it never reads either.

	WHY mod 12 AND NOT mod 16.  Units +12..+15 of a pad are SUB+4..+7,
	the region's segment offsets 0..3, which are an ALLOWANCE and
	cannot fire by design (defect 3).  A probe that expected them to
	fire would be asserting the guard model is wrong.  (5i+3) mod 12
	over i = 0..10 gives {3,8,1,6,11,4,9,2,7,0,5}: eleven distinct
	guarded offsets, no two pads alike, and it avoids the two traps -
	pad 8's TAIL+0, which loadpv legitimately writes, and pad 5's
	SUB+2..+7, which digit_at legitimately writes.

	WITNESS(i) = 0xB0B00000 + 17i + (clean read AND 255).  The last
	term is what makes the dirty read a READ: the poison differs by
	zone role (0xA5 in a TAIL, 0x5A in a SUB), so no single literal
	can stand in for it.  STATED LIMIT: a saboteur who reads this
	comment can still recompute the value instead of loading it.  The
	load-bearing units are 0, 2 and 3 - stubbing the walker moves
	those, and the test proves it by stubbing the walker. )

"TW canary battery"
	( the CLEAN pass first: a canary that always fires cannot pass )
	=> MEM poison pads;

( battery 8 - THE LONG-HORIZON SERVO REPLAY                             )
( ==================================================================== )

      ( CRITICAL 1.  [Counts] is 32 bits and wraps every 2^32 counts =
	477.3 s at 8999 cpms.  The old servo divided
	([Counts] - [TKsrv0c]) by the milliseconds since TK START, so the
	numerator wrapped while the denominator grew without bound: 1840
	cpms at t = 600 s against a true 8999, 4226 at t = 900 s, and the
	+-1% clamp turned the one-shot collapse into a PERMANENT ratchet.

	The old battery this replaces asked six SINGLE questions with the
	elapsed time varied, which could never see the ratchet: the
	ratchet is what a SEQUENCE of firings does to each other.  And
	Wave 5's test then XFAILed the answer, so the defect was asserted
	rather than fixed.

	THIS REPLAYS A WHOLE RUN.  A synthetic free-running counter

	    C(t) = (C0 + cpms*t) mod 2^32

	is evaluated at the ends of TWHFIRE consecutive windows of TWHWIN
	ms each, 19.9 simulated minutes, and the servo is driven from it
	THREE WAYS on the same timeline:

	  1 WINDOWED, shipped estimator
	      srvcnt = C(t) - C(t-w),  srvms = w        the fix
	  2 ANCHORED, shipped estimator
	      srvcnt = C(t) - C(0),    srvms = t        the old bracket
	  3 ANCHORED, ORIGINAL estimator
	      the same, through the pre-correction arithmetic: an
	      UNSIGNED '< 500 band with no upper bound, a TRUNCATING
	      divide and a +-1% clamp whose step has no floor

	Legs 1 and 2 call the SAME unmodified "TK servo apply" out of
	work/fbtick.txt.  Leg 3 is written out here because the code it
	models no longer exists anywhere - it is the defect, and it is the
	POSITIVE CONTROL.  Without it the battery would be worthless:
	leg 2 alone recovers, because SRVMAX refuses every bracket past 60
	s, so a run that only compared 1 against 2 would report success
	for reasons that have nothing to do with the wrap.  Leg 3 is what
	makes "the windowed servo holds across the wrap" a claim that
	could have come out false.

	SEEDED OFF THE TRUE RATE, deliberately.  [TKcpms] starts 4% low,
	so a servo that did nothing at all scores a 4% error and fails.
	The graded quantity is therefore CONVERGENCE - the estimator has
	to walk the +-1% clamp up to the true rate and then stay there
	across every wrap - not the tautology "an estimator seeded at the
	answer returns the answer".

	C0 IS A SYNTHETIC ORIGIN, and that is the whole point.  Seven
	scenarios place the 2^32 crossing at seven different phases -
	before the run, in the first millisecond, mid-window, exactly on a
	window boundary, and at three later times - so the replay is not
	at the mercy of when the machine happened to boot.  Waiting eight
	minutes is not a test; setting the origin is.

	Scenario 6 is the ADVERSARIAL one: cpms = 1,000,000, a host about
	111x faster than this one.  There a single TWHWIN window already
	encodes 1.4e10 counts, which itself aliases 2^32, and the WINDOWED
	servo fails too - because SRVMAX is the literal 60000 rather than
	anything derived from cpms.  The boundary is cpms > 2^32/SRVMAX =
	71,583; this host reports about 9,000.  That is recorded, not
	hidden: it is the part of CRITICAL 1 this wave did not close.

	Sixteen units per scenario:
	   0 C0                     1 true cpms
	   2 windowed final cpms    3 windowed worst |err| after settling
	   4 wrapped windows        5 subtraction mismatches
	   6 why-code bitmask       7 seed cpms
	   8 anchored-new final     9 anchored-new worst |err|
	  10 anchored-OLD final    11 anchored-OLD worst |err|
	  12 firings               13 window ms
	  14 final t               15 firings to first exact hit )

	[TWhc0] = 4294967295; [TWhcp] = 8999;    => TW hor one;

( ==================================================================== )
( battery 8b - THE CLASS-A 16-BIT WRAP, AT THE TRUNCATION POINT         )
( ==================================================================== )

      ( CRITICAL 2.  Decision 3 class A used to be "allocate the full
	segment, cost 1,540 units, no code".  AN ALLOCATION SIZE CANNOT
	REPRODUCE A WRAP.  Under DOS the write folded back to offset 0 of
	the segment; under 32-bit unit addressing it walks linearly past
	the region end through whatever follows, and no size stops that.

	The mechanism is a MASK, and it belongs where the ORIGINAL
	truncates, which is not the same place for the two sites:

	  spot    NOCTIS-0.CPP:4485.  The truncation point IS the 16-bit
	          DI, formed AFTER both adds, so mask and address coincide:
	              masked = SPBG + ((4 + py + px) AND 65535)
	  cirrus  NOCTIS-0.CPP:4715.  "mov bx,py / add bx,px" truncates in
	          BX and only THEN shifts right, so the mask is one step
	          earlier:
	              masked = SOBJ + ((((py+px) AND 65535) >> 1) + 4)

	The two failure deltas therefore DIFFER - 65,536 for spot,
	32,768 for cirrus.  A single "mask the final index" helper would
	halve cirrus's error and still be wrong, and that is what makes
	the difference between the deltas a graded quantity rather than a
	restatement: min and max of each delta are recorded separately and
	w5spec.py derives both from the arithmetic.

	The mask is taken against the SEGMENT ORIGIN, not the buffer base.
	SEG is R* minus 4 for every farmalloc'd block, so a masked offset
	of 0..3 lands on the four header units below the buffer - the SUB
	zone's allowance, not a violation.

	Four units per site: calls, wraps, delta-min, delta-max. )

      ( ONE TRUNCATION PER SITE, and this is not cosmetic.  The first
	version of this battery masked C through "MEM u16 site" and then
	handed the ALREADY MASKED value to "MEM seg addr", which masks
	again - so spot's fold was applied twice and deleting either mask
	on its own left spot's answer unchanged.  The sabotage that
	deletes a mask was then caught only by cirrus, which is a check
	passing for the wrong reason.  So spot now hands "MEM seg addr"
	the RAW offset and lets it truncate, and "MEM u16 site" is used
	for its COUNTER; cirrus still truncates early, in BX, because that
	is where the original truncates.  Each mask is now the only thing
	standing between one site and a linear walk. )

( the soak                                                             )
( ==================================================================== )

      ( The soak is BRACKETED BY THE OTHER CLOCK.  T12 used to convert the
	counter span into milliseconds with [TKcpms] and compare that
	against the nominal grid - which stopped meaning anything the
	moment the servo started running, because cpms then CHANGES during
	the soak and the conversion measures the servo's own correction
	rather than any drift.  READ TIME is a genuinely different clock
	from the high-performance counter, so bracketing the soak with it
	turns T12 into two independent clocks agreeing on how long 200
	periods took.  Its granularity is about 1 ms, which over 11 s is
	small enough for the bound to still catch a period of 55 ms
	instead of 54.9254. )

"TW soak"
	=> TK read wall; [twself plus 86] = [TKtmp];
	=> TK start;
	[TWi] = 0;
    "TW sk loop"
	=> TW page build;
	=> TW expand;

	( a deterministic hitch, so skip-to-grid is TESTED not asserted )
	A = 0; A + TWHITCH; ? A = 0 -> TW sk nohitch;
	A = [TWi]; A+; A % TWHITCH;
	? A != 0 -> TW sk nohitch;
	[TKtmp] = 0; [TKtmp] + TWHITMS; => TK burn;
    "TW sk nohitch"

	=> TK step;
	[TWi]+;
	A = [TWi]; ? A '< TWNTICK -> TW sk loop;
	=> TK read wall; [twself plus 87] = [TKtmp];
	end;
